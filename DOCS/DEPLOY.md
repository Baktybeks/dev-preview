## Deploy guide

Этот документ описывает общий процесс подготовки и выкладки FrontPrep в прод.  
Конкретные команды могут отличаться в зависимости от хостинга (VPS, static hosting + reverse proxy и т.д.).

---

## 1. Предварительные требования

- Аккаунт **Appwrite** и развёрнутый инстанс (Docker или облако).
- Настроенный проект в Appwrite:
  - база данных (Database / Tables);
  - API‑ключи с ограниченными правами для frontend и скриптов.
- Node.js (LTS), npm.

---

## 2. Конфигурация окружения

Создайте `.env` (или используйте другой поддерживаемый Vite‑формат, например `.env.production`) с переменными:

- `VITE_APPWRITE_ENDPOINT` — URL инстанса Appwrite.
- `VITE_APPWRITE_PROJECT_ID`
- `VITE_APPWRITE_DATABASE_ID`
- ID таблиц (`VITE_APPWRITE_TABLE_USERS`, `VITE_APPWRITE_TABLE_CATEGORIES`, `VITE_APPWRITE_TABLE_QUESTIONS`, `VITE_APPWRITE_TABLE_STATUS`, `VITE_APPWRITE_TABLE_FAVORITES`) — если используются.
- Ключи/ID для скриптов и прочие настройки по проекту.

Убедитесь, что:
- переменные используются в `appwriteClient` / `appwriteConfig`;
- чувствительные значения **никогда не попадают** в клиентский бандл без необходимости.

---

## 3. Инициализация и миграции БД

На CI или локально (перед первым деплоем/после изменения схемы):

```bash
npm install

# Создание/обновление схемы
npm run db:setup

# Первичное наполнение
npm run db:seed
```

Доп. утилиты:

- `npm run db:reset` — сброс БД до чистого состояния (использовать осторожно).
- `npm run db:deleteAttribute` / `npm run db:reset-setup` — точечные миграции схемы.

---

## 4. Продакшн‑сборка фронтенда

```bash
npm install
npm run build
```

В результате появится папка `dist/`:
- `index.html`
- JS/CSS‑чанки в `dist/assets/`
- отчёт `dist/stats.html` (если включён `rollup-plugin-visualizer`)

Проверьте локально:

```bash
npm run preview
```

По умолчанию Vite Preview стартует на `http://localhost:4173`.

---

## 5. Развёртывание статики

Варианты:

1. **Static hosting (S3 + CloudFront, Netlify, Vercel, static сайт на Nginx)**:
   - загружаем содержимое `dist/` на хостинг;
   - настраиваем:
     - кеширование для `assets/*` (долгое, с immutable);
     - всегда отдавать `index.html` для SPA‑роутов (`/categories/*`, `/admin/*` и т.д.).

2. **Свой сервер (Nginx/Apache)**
   - корень сайта указывает на `dist/`;
   - правило `try_files`/`fallback` на `index.html` для всех неизвестных путей;
   - включить gzip/brotli (желательно), ETag, кеширование статики.

Пример для Nginx (упрощённо):

```nginx
location / {
  root   /var/www/frontprep/dist;
  try_files $uri /index.html;
}
```

## 6. Конфигурация домена и HTTPS

- Привяжите домен к хостингу (A/CNAME записи).
- Включите HTTPS:
  - Let’s Encrypt / ACME‑клиент;
  - или встроенный SSL вашего провайдера.

Проверьте:
- корректность редиректов HTTP → HTTPS;
- CORS/headers со стороны Appwrite (если фронт и Appwrite на разных доменах).

---

## 7. Проверка после деплоя

Ручной чек‑лист:

- Главная и базовая навигация (категории, вопросы, прогресс, профиль).
- Логин/регистрация:
  - создание пользователя;
  - первый пользователь получает `isAdmin: true`.
- Auth/role:
  - обычный пользователь не имеет доступа к `/admin`;
  - админ видит `/admin` и может назначать/снимать `admin` с других.
- Работа с вопросами:
  - бесконечный скролл;
  - изменение статусов;
  - добавление/удаление из избранного.
- Admin:
  - дашборд со статистикой;
  - управление вопросами (CRUD, импорт JSON);
  - управление пользователями (роль admin).
- Ограничение по ширине:
  - не‑админ: на десктопе видит заглушку «Только мобильные и планшеты»;
  - админ: может использовать все страницы на любой ширине.

---

## 8. Observability и обновления

Рекомендуется:

- Включить логи/метрики на уровне Appwrite (ошибки, таймауты).
- Мониторинг доступности фронта (health‑checks через внешнюю систему).
- При изменениях схемы:
  - сначала откатить/внести новую схему (миграции);
  - затем деплойнуть новую версию фронта.
