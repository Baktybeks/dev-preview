## Overview

**FrontPrep** — веб‑приложение для подготовки к собеседованиям по фронтенду.  
Основные части:
- **Пользовательская часть**: категории, вопросы, прогресс, профиль.
- **Админка**: статистика, управление вопросами, управление пользователями.

Приложение ориентировано на мобильное/планшетное отображение. На десктопе:
- для обычных пользователей показывается заглушка «Только мобильные и планшеты»;
- **администраторы** могут использовать все страницы на любой ширине.

## Tech stack

- **Frontend**: React + TypeScript
- **Routing**: `react-router-dom`
- **State / data**:
  - `@tanstack/react-query` — серверное состояние
  - `zustand` — auth‑store
- **Backend / DB**: Appwrite (Tables)
- **Build**: Vite (`vite`, `@vitejs/plugin-react-swc`)

## Getting started

1. **Установка зависимостей**
   ```bash
   npm install
   ```

2. **Конфигурация окружения**
   - Скопируйте пример `.env` (если есть) или создайте свой.
   - Укажите параметры Appwrite (endpoint, projectId, keys и т.д.).
   - Убедитесь, что скрипты в `scripts/` могут подключаться к Appwrite.

3. **Инициализация БД Appwrite**
   Скрипты находятся в `scripts/`:
   - `npm run db:setup` — создание коллекций/таблиц.
   - `npm run db:seed` — первичное наполнение.
   - Дополнительные утилиты: `db:reset`, `db:deleteAttribute`, `db:csv2seed` и др.

4. **Запуск в dev‑режиме**
   ```bash
   npm run dev
   ```

5. **Продакшн‑сборка**
   ```bash
   npm run build
   npm run preview
   ```

## Auth и роли

- Авторизация и профиль хранятся в Appwrite.
- Первый созданный пользователь автоматически получает `isAdmin: true`.
- Состояние авторизации:
  - `src/store/authStore.ts` — zustand‑хранилище, методы `loadUser`, `logout`.
  - `getUserProfile` / `ensureUserProfile` в `src/api/authApi.ts`.

### Admin доступ

- **Маршруты /admin** защищены `AdminGuard` (`src/components/admin/AdminGuard.tsx`):
  - проверяет, что пользователь залогинен;
  - проверяет, что `profile.isAdmin === true`;
  - в противном случае редиректит на `/`.

- **Ограничение по ширине экрана**:
  - реализовано в `ViewportGuard` (`src/components/layout/ViewportGuard.tsx`);
  - на десктопе блокирует приложение только для **не‑админов**;
  - админ (по `profile.isAdmin`) видит все маршруты на любой ширине.

## Навигация и маршруты

Все маршруты описаны в `src/App.tsx`:

- `/login`, `/register` — экраны аутентификации.
- Основной shell (`BottomTabLayout`):
  - `/` — Home.
  - `/categories` — список категорий.
  - `/categories/:id/questions` — вопросы по категории (infinite scroll).
  - `/progress` — прогресс и избранные.
  - `/profile` — профиль пользователя.
  - `/favorites` → редирект на `/progress`.
- Admin:
  - `/admin` — дашборд.
  - `/admin/questions` — управление вопросами.
  - `/admin/users` — управление пользователями.

Все экраны загружаются **лениво** (`React.lazy` + `Suspense`), что уменьшает размер начального бандла.

## Admin: управление вопросами

Экран: `src/screens/Admin/AdminQuestionsScreen.tsx`.

Возможности:
- поиск/фильтр по тексту, категории, сложности;
- бесконечный скролл списка вопросов;
- создание/редактирование/удаление вопросов;
- массовое удаление выбранных вопросов;
- **импорт вопросов из JSON**.

### Импорт из JSON

В админке есть аккордеон **«Импорт из JSON»**:

- Вверху — редактируемый **шаблон** (textarea), который задаёт структуру импортируемых объектов.
- Ниже — поле для JSON, кнопка «Проверить и превью» и кнопка «Импортировать».

#### Шаблон

Стартовое значение:

```json
[
  {
    "title": string,
    "answer": string,
    "category": string,
    "categorySlug": string,
    "tags": [string],
    "difficulty": "easy | medium | hard"
  }
]
```

Шаблон:
- можно редактировать;
- можно сбросить к дефолтному состоянию кнопкой «Сбросить».

#### Проверка по шаблону

- При нажатии «Проверить и превью»:
  1. Парсится текущий текст шаблона → строится схема полей (тип `string`, `string[]`, `enum`).
  2. Парсится JSON из поля импорта.
  3. Данные валидируются по схеме:
     - присутствие полей;
     - корректный тип (строка, массив строк, enum‑значения).
- При ошибке выводится сообщение вида:
  - `Шаблон: ...` — если некорректен шаблон;
  - `Запись N: ...` — если некорректны данные.
- При успехе показывается превью (количество записей) и становится доступна кнопка «Импортировать».

#### Реальный импорт

- Реализован в `src/api/adminApi.ts` функцией `importQuestions`.
- Поддерживает:
  - `title` или `question` (одно из полей обязательно);
  - `answer` — текст ответа;
  - `category` или `categorySlug` — маппятся через справочник категорий (имена и slug);
  - `tags?: string[]` — необязательные теги;
  - `difficulty?: string` — алиасы:
    - `easy`, `medium`, `hard`;
    - допускаются алиасы `junior` → `easy`, `middle` → `medium`, `senior` → `hard` (внутри кода).

Ошибки импорта собираются и показываются после операции (количество созданных и число ошибок).

## Оптимизация бандла и анализ

### Разделение вендоров

В `vite.config.ts` настроен `build.rollupOptions.output.manualChunks`:

- `react` — React + ReactDOM.
- `router` — `react-router-dom`.
- `react-query` — `@tanstack/react-query`.
- `appwrite` — SDK Appwrite.
- `zustand` — zustand.

Это уменьшает размер начального чанка приложения и улучшает кеширование вендорных библиотек.

### Ленивая загрузка экранов

В `App.tsx`:
- Все экранные компоненты импортируются через `React.lazy(...)`.
- Маршруты обёрнуты в `<Suspense fallback="Загрузка…">`.
- Код каждого экрана (включая админские) подгружается только при переходе к нему.

### Анализ размера бандла

Подключён `rollup-plugin-visualizer`:

- После `npm run build` генерируется `dist/stats.html`.
- В нём показана интерактивная карта (treemap) чанков/модулей и их размеров (включая gzip/brotli).
- Можно использовать для поиска тяжёлых зависимостей и оценки эффекта оптимизаций.

## Где что лежит (быстрый обзор структуры)

- `src/api` — работа с Appwrite и серверными данными (`questionsApi`, `adminApi`, `authApi`, `progressApi` и др.).
- `src/screens` — экранные компоненты (Home, Categories, Questions, Progress, Profile, Admin*).
- `src/components` — переиспользуемые компоненты (layout, admin, auth‑модалки и т.п.).
- `src/store` — zustand‑хранилища (в т.ч. `authStore`).
- `src/hooks` — кастомные хуки (например, `useAdminNav`, `useAuthGuard`).
- `scripts` — вспомогательные Node‑скрипты для Appwrite (setup, seed, reset и т.д.).
